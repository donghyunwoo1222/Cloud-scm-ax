# 금액 규칙 (외화 발주, #267 PR 0)

> 코드: `backend/app/services/po_money.py`(순수 함수), 테스트: `backend/tests/test_po_money.py`. 이 PR 은 계산 함수와 규칙만 만들고 DB·API·화면은 바꾸지 않는다(Refs #282).

## 규칙

1. **저장 방식**: 외화 금액 + 환율 + 원화 환산 금액을 모두 저장한다. 원화는 계산해서 스냅샷으로 저장한다(나중에 환율을 바꿔도 이미 낸 발주의 원화는 변하지 않는다).
2. **환율**: 소수 둘째 자리까지. 통화마다 기준 단위가 있고(JPY·VND 는 100, 나머지 1), 입력은 "기준 단위당 원"이다. 예) 100엔 = 905.12원.
3. **원화 환산** = (줄별 외화 금액의 합) × 환율 ÷ 기준 단위. **줄별로 버리지 않고 총액에서 한 번만** 원 미만을 버린다(`ROUND_DOWN`).
4. **줄 외화 금액** = 수량(정수) × 외화 단가(Decimal), 정확한 값(반올림 없음).
5. **줄 표시**: 줄에는 외화 금액만 보여 주고, 원화는 총액 한 곳에만 보여 준다(줄마다 원화를 보이면 합계와 1~2원 어긋나 보인다).
6. **고정 시점**: 환율·원화 환산은 승인 때 고정한다. 바꿔야 하면 취소 후 새로 작성한다.
7. **계산 도구**: Decimal 과 `ROUND_DOWN` 만 쓴다. float 입력은 `TypeError`, 파이썬 `round()` 는 쓰지 않는다. 모듈 전용 컨텍스트(`CTX`: 60자리, 곱셈·덧셈에서 반올림이 필요하면 `Inexact` 오류)를 쓰고 전역 컨텍스트(기본 28자리)는 바꾸지 않는다. 계획의 상한 안에서는 `Inexact` 없이 정확하고, 한도(60자리)를 넘으면 조용히 반올림하지 않고 `MoneyError` 가 된다. 마지막 정수 변환만 버림이 허용된다. 문자열 금액은 `1350`·`1350.250` 모양만 받는다(지수 `1e3`, 아라비아·전각 숫자, 부호 `-0` 은 거절).
8. **외화 단가 자릿수**: 단가는 통화의 소수 자릿수를 넘으면 거절한다(USD 0.035 거절, JPY 소수 거절). 센트 미만 단가는 지원하지 않는다.
9. **원가** = 품목 원화 합계 + 운송비 + 부대비용 합계(부가세 미포함). 운송비·부대비용은 원화 정수. 운송비 NULL(미입력)과 0 은 다르다(`cost_total` 이 `missing=["freight"]` 로 알려 준다).
10. **외화 부가세 기준은 보류**(#268 에서 결정). 이 PR 에는 부가세 계산이 없다.

## 입고 기준 계산 (`received_goods_krw`)

입고한 만큼의 원화 합계도 발주 시 총액(`goods_krw_total`)과 **같은 규칙**(줄별로 버리지 않고 총액에서 한 번만 원 미만 버림)을 쓴다. 다만 박스 줄은 낱개 단가가 나누어떨어지지 않을 수 있어, 줄 금액 = 입고한 재고 단위 수 × 가격 ÷ per(그 가격이 몇 재고 단위당인지)를 분수(`Fraction`)로 정확히 구해 모두 더하고, 외화면 × 환율 ÷ 기준 단위를 한 뒤 맨 끝에서 한 번만 버린다. 낱개 단가 줄은 per = 1, 박스 단가 줄은 per = 박스당 낱개 수다. 예) 1,000원 3개입 박스에서 4개 입고 → 4 × 1,000 ÷ 3 = 1,333.33… → 1,333원. 박스를 전부 입고하면 발주 시 총액과 같은 값이 나온다.

## 저장과 API (#267 PR 1)

- 칸: 발주서 `currency`·`rate_unit`·`exchange_rate`(Numeric 12,2)·`krw_goods_total`(승인 때 고정)·`freight_amount`·`extra_costs`, 줄 `fx_unit_price`·`fx_box_unit_price`(Numeric 14,2). 자세한 뜻은 `erd.md`.
- 계산 위치: `purchase_orders.goods_krw_of`(품목 원화 합계 → `goods_krw_total`), `cost_of`(원가·입고 기준 → `cost_total`·`received_goods_krw`). 화면·내보내기는 이 값만 쓴다.
- 입력 상한은 스키마(`schemas/common.py` 의 `FxPrice`·`ExchangeRate`·`BigWon`, 줄 2,000·수량 100만)가 먼저 막아, 이 모듈은 위 상한 테스트 범위 안의 값만 받는다. 금액 규칙 위반(`MoneyError`)은 422 `VALIDATION_ERROR` 다.
- 외화 단가·환율을 **문자열**로 보내면 `to_decimal` 과 같은 모양만 받는다: ASCII 숫자와 소수점 하나("12.50"). 지수("1e1"), 전각·다른 문자 숫자("１２"), 부호("-0", "+1"), 앞뒤 공백, "1.", "NaN" 은 422. JSON 숫자(12.5)는 그대로 받는다.
- DB 도 막는다: 통화와 기준 단위가 어긋나는 행(`ck_purchase_orders_rate_unit`), 승인한 적 있는 외화 발주서의 환율 NULL(`ck_purchase_orders_fx_rate_approved`).
- 승인 뒤 환율 정정은 없다. 잘못 넣었으면 취소 후 새로 작성한다.

## 알려진 한계

- 상한 테스트가 확인한 범위(줄 2,000, 수량 1,000,000, 단가 99,999,999.99, 환율 9,999.99) 밖의 값은 입력 검증에서 막는다(PR 1 스키마).
- 외화 단가는 통화 최소 단위까지만 받는다. 센트 미만 단가(예: 0.035달러)는 지원하지 않는다.
