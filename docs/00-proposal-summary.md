# 대표 과제 제안서 요약: 중소기업용 Cloud SCM + AX

이후 모든 산출물의 기준이 되는 제안서(5~8장) 요약입니다.

## 목표

중소 제조·유통업체가 고가 ERP/SCM 없이 웹에서 품목·공급업체·입출고·재고·발주를 관리하고, 데이터와 AI로 재고 부족·과잉을 조기에 파악하는 Cloud SCM MVP를 구현한다.

## 단계별 산출물 (10단계)

1. 벤치마킹 (완료)
2. 문제 정의 (완료, 인터뷰 검증 대기)
3. 서비스 기획: 요구사항, 업무 흐름, 화면 흐름
4. AX 설계: 기능 명세, 검증 기준
5. MVP 범위 확정: Must/Should/Could, 완료 기준
6. 시스템 설계: ERD, API, Architecture
7. 구현
8. 배포 (서비스 URL)
9. 검증 (사용자 테스트)
10. 포트폴리오화: GitHub, README, Demo

## MVP 범위

- 필수: 회사/사용자, 공급업체, 품목/자재(단가·안전재고·리드타임), 입출고, 현재 재고, 발주, 대시보드
- AX 필수 후보: AI 발주 추천
- AX 선택: 자연어 SCM 질의
- 후순위: 고급 수요예측
- 제외: 회계·급여·전사 ERP
- AX 우선순위: 1 재고 부족·과잉 탐지, 2 적정 발주량 추천, 3 자연어 질의, 4 주간 요약, 5 공급망 리스크 알림

## 데이터 모델 최소 구조

`Company → Users / Suppliers / Products / Inventory / Inbound / Outbound / PurchaseOrders / InventoryMovements`

- 모든 업무 데이터에 `company_id`
- 재고는 입출고 이력으로 설명 가능하게
- 발주 상태: DRAFT → APPROVED → ORDERED → RECEIVED / CANCELLED

## 기술 스택 (권장)

Next.js(React) / FastAPI 또는 Django / PostgreSQL / Python+Pandas+SQL / LLM API / GCP 또는 AWS / GitHub

## 검증·포트폴리오

- 사용자 테스트 5~10명. 대표 시나리오: 품목 등록 → 입고 → 출고 → 부족 확인 → 발주 생성
- KPI: 재고회전율, 품절 위험 품목 수, 안전재고 미만, 장기재고, 월 입출고량, 발주 리드타임, 납기 준수율
- 면접 설명 축: 어떤 중소기업 문제 → 어떤 업무 규칙 → 데이터·AI로 어떤 의사결정 지원
- 포트폴리오 10항목: 문제 정의, 벤치마킹, 본인 역할, 업무 모델, 기술 근거, AX 가치, 문제 해결, 검증, 결과, 한계/확장
