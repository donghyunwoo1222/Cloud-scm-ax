# 금액 규칙 (외화 발주, #267 PR 0)

> 코드: `backend/app/services/po_money.py`(순수 함수), 테스트: `backend/tests/test_po_money.py`. 이 PR 은 계산 함수와 규칙만 만들고 DB·API·화면은 바꾸지 않는다(Refs #282).

## 규칙

1. **저장 방식**: 외화 금액 + 환율 + 원화 환산 금액을 모두 저장한다. 원화는 계산해서 스냅샷으로 저장한다(나중에 환율을 바꿔도 이미 낸 발주의 원화는 변하지 않는다).
2. **환율**: 소수 둘째 자리까지. 통화마다 기준 단위가 있고(JPY·VND 는 100, 나머지 1), 입력은 "기준 단위당 원"이다. 예) 100엔 = 905.12원.
3. **원화 환산** = (줄별 외화 금액의 합) × 환율 ÷ 기준 단위. **줄별로 버리지 않고 총액에서 한 번만** 원 미만을 버린다(`ROUND_DOWN`).
4. **줄 외화 금액** = 수량(정수) × 외화 단가(Decimal), 정확한 값(반올림 없음).
5. **줄 표시**: 줄에는 외화 금액만 보여 주고, 원화는 총액 한 곳에만 보여 준다(줄마다 원화를 보이면 합계와 1~2원 어긋나 보인다).
6. **고정 시점**: 환율·원화 환산은 승인 때 고정한다. 바꿔야 하면 취소 후 새로 작성한다.
7. **계산 도구**: Decimal 과 `ROUND_DOWN` 만 쓴다. float 입력은 `TypeError`, 파이썬 `round()` 는 쓰지 않는다. 모듈 전용 컨텍스트(`CTX`: 60자리, 곱셈·덧셈에서 반올림이 필요하면 `Inexact` 오류)를 쓰고 전역 컨텍스트(기본 28자리)는 바꾸지 않는다. 마지막 정수 변환만 버림이 허용된다.
8. **외화 단가 자릿수**: 단가는 통화의 소수 자릿수를 넘으면 거절한다(USD 0.035 거절, JPY 소수 거절). 센트 미만 단가는 지원하지 않는다.
9. **원가** = 품목 원화 합계 + 운송비 + 부대비용 합계(부가세 미포함). 운송비·부대비용은 원화 정수. 운송비 NULL(미입력)과 0 은 다르다(`cost_total` 이 `missing=["freight"]` 로 알려 준다).
10. **외화 부가세 기준은 보류**(#268 에서 결정). 이 PR 에는 부가세 계산이 없다.

## 함수 (`po_money.py`)

`to_decimal`, `parse_rate`, `check_fx_price`, `fx_line_amount`, `krw_of`, `goods_krw_total`, `cost_total`, `unit_price_of_box`, `received_fx_amount`. 규칙 위반은 `MoneyError`(`ValueError`), 자료형 오류(float·bool)는 `TypeError`.

## 고정한 테스트 숫자

| 경우 | 계산 | 결과 |
|---|---|---|
| 원 미만 한 번 버림 | 3개 × 0.50달러 × 1,350.25 = 2,025.375 | 2,025원 |
| 총액 버림 vs 줄별 버림 | 1달러 3줄 × 환율 1,350.75 | 총액 4,052원 (줄별 버림이면 4,050원) |
| 엔화 기준 단위 100 | 10,000엔 × 905.12 ÷ 100 | 90,512원 |
| 입고 기준 박스 줄 | 박스 단가 10,005원, 10개입 → 45개 입고 | 45,022.5 → 45,022원 (KRW 경로) |
| 원가 합산 | 품목 1,380,000 + 운송비 120,000 + 부대비용 30,000 | 1,530,000원 |
| 운송비 미입력 | freight=None | 합계는 계산, missing 에 "freight" |
| 운송비 0 | freight=0 | missing 아님 |
| 기존 KRW 회귀 | 1,005원 × 3줄 | 공급가액 3,015원 (부가세는 기존 `vat_of` 로 301, 읽기만 비교) |

| 거절 | float, USD 0.035, JPY 0.5, 환율 0·음수·소수 셋째 자리, 기준 단위 50, 미지원 통화 | 예외 |

## 알려진 한계

- `unit_price_of_box` 는 박스 단가가 낱개 수로 나누어떨어지지 않으면(1,000 ÷ 3) `MoneyError` 를 낸다. 나머지를 자르면 합계가 정수 경계에서 1원 어긋날 수 있어서다. 입고 기준 계산에서 이런 박스가 필요하면 PR 1 에서 "수량 × 박스 단가를 먼저 곱한 뒤 낱개 수로 나누는" 방식을 정한다.
- 상한 테스트가 확인한 범위(줄 2,000, 수량 1,000,000, 단가 99,999,999.99, 환율 9,999.99) 밖의 값은 입력 검증(PR 1)에서 막아야 한다.
