## 프로젝트 한눈에 보기

중소 규모의 로트·유통기한 관리가 필요 없는 공산품·생활용품 유통업체가 재고, 입출고, 발주, 공급업체를 한 서비스에서 관리하고, 여기에 데이터 분석과 AI 추천을 붙이는 클라우드 SCM 서비스를 직접 기획·구현·배포하는 개인 프로젝트입니다.

**왜 이 프로젝트인가.** 중소기업은 재고는 엑셀로, 발주는 메신저로, 판매는 쇼핑몰 관리자로 따로 관리하는 경우가 많다는 가설에서 출발합니다. 이 가설은 아직 사용자 인터뷰로 검증하지 않았습니다. 목표는 분석 리포트 한 편에 그치지 않고, 직무 이해, 서비스 기획, 데이터 모델링, 업무 프로세스, AX 활용, 시스템 구현 능력을 한꺼번에 보여주는 것입니다.

**차별점(현재 가설).** 재고 부족 감지 → 발주서 초안 → 공급업체 납기 관리 → 수요 예측 기반 추천을 한 흐름으로 잇는 것입니다. 근거는 아래 GAP 분석에 있습니다.

| 단계 | 내용 | 산출물 | 상태 |
| --- | --- | --- | --- |

## 조사 개요

2026-11-02 기준으로 직접 열어 확인한 공개 자료(공식 페이지, 언론 보도, 일부 제3자 리뷰·블로그)만 사용해, 국내 6개·해외 3개 서비스를 비교했습니다. 확인하지 못한 항목은 "확인 불가"로 남겼습니다.

**선정 기준**

- 중소 제조·유통·셀러가 쓸 수 있는 재고/입출고/발주 기능이 있는 클라우드 서비스
- 공식 사이트나 보도에서 기능·가격 근거를 확인할 수 있는 서비스
- ERP, 채널 연동형 OMS/WMS, 해외 SaaS를 섞어 유형이 겹치지 않게 구성

**한계**

- 로그인 후 화면은 직접 써보지 못해, UX는 공식 페이지 설명과 공개 자료 기준의 간접 평가입니다.
- 더존·파스토는 가격이 견적제이고, 영림원은 현행 구독료가 공개되지 않아 2020년 자료만 확인되며, 플레이오토·사방넷은 요금제가 자주 바뀝니다.
- 일부 가격은 제3자 자료이며, 해당 칸에 따로 표시했습니다.

## 벤치마킹 대상 9개

국내는 범용 ERP 3개, 셀러 채널 연동 2개, 풀필먼트 대행 1개이고 해외는 소규모 재고 SaaS 2개와 모듈형 ERP 1개입니다. 국내는 요청하신 5개에 파스토를 더해 6개입니다.

| 구분 | 서비스 | 유형 | 선정 이유 |
| --- | --- | --- | --- |
| 국내 | 이카운트 ERP | 클라우드 범용 ERP | 중소기업 점유율이 높고 월 정액 가격이 공개됨 |
| 국내 | 더존 아마란스10 | 업무 플랫폼형 ERP | 중견·중소기업 대상이고 물류관리(재고·입출고·발주입고·바코드) 기능이 자세히 공개됨 |
| 국내 | 영림원 시스템에버 | 클라우드 ERP(제조·유통) | 중소기업 특화를 내세우고 AI 분석 기능을 소개함 |
| 국내 | 사방넷 2.0 | 셀러용 OMS+WMS | 주문·재고·창고를 한 화면에서 묶는 사례 |
| 국내 | 플레이오토 | 셀러용 주문·재고 관리 | 요금제가 공개되어 가격 비교가 가능 |
| 국내 | 파스토(FASSTO) | 풀필먼트(3PL)+FMS | 재고를 직접 보관하지 않는 셀러의 물류 흐름과 과금 방식 비교 기준 |
| 해외 | Zoho Inventory | 소규모 재고 SaaS | 플랜별 한도와 가격이 명확해 요금 구조 비교에 좋음 |
| 해외 | Katana | 소규모 제조 재고·MRP SaaS | 중소 제조에 특화되고 AI 보충(Replenishment)을 제공 |
| 해외 | Odoo Inventory | 모듈형 오픈소스 ERP | 보충 규칙과 자동 발주 흐름이 자세히 공개됨 |

더존 스마트A는 제3자 자료([korea-erp.com](https://korea-erp.com/smart-a-discontinued/), 2025-06-20)에서 2023-12-31 신규 판매 중단·2025-12-31 지원 종료로 확인되어 아마란스10으로 바꾸었습니다. 파스토는 공식 사이트([서비스 소개](https://fassto.ai/content/page/services), [비용 안내](https://www.fassto.ai/view/service-cost))를 열어 확인했고, 보도 한 건은 다른 서비스 내용이어서 쓰지 않았습니다.

아래는 유형 이름이 무엇을 뜻하는지 설명한 표입니다. 장단점은 해당 유형의 일반적인 성격이며, 서비스마다 다를 수 있습니다. 우리 프로젝트와의 관계는 이 조사의 GAP 결과를 바탕으로 써습니다.

| 유형 | 쉽게 말하면 | 장점 | 단점 | 대표 서비스 |
| --- | --- | --- | --- | --- |
| 클라우드 범용 ERP | 회계·재고·판매·구매를 인터넷으로 한꺼번에 쓰는 업무 프로그램 | 기능이 넓고 가격이 합리적임(이카운트는 월 정액이 공개됨) | 업종 특화가 약하고 화면이 많아 초보자에게 복잡할 수 있음 | 이카운트 |
| 업무 플랫폼형 ERP | ERP를 기본으로 하고 여러 업무 기능을 한 플랫폼에 모아 놓은 큰 시스템 | 물류·회계·인사 등 필요한 업무를 한 곳에서 확장 가능 | 도입에 시간·비용이 들고 중견기업 중심이라 소규모에는 무겁음 | 더존 아마란스10 |
| 클라우드 ERP(제조·유통) | 제조와 유통 업종에 맞춰 만든 ERP | 업종 특화 기능과 분석 기능 제공 | 가격이 견적 중심이라 비교하기 어려울 수 있음 | 영림원 시스템에버 |

| 소규모 재고 SaaS | 재고와 주문 중심의 가벼운 구독형 프로그램 | 플랜별 한도와 가격이 명확하고 시작이 쉽다 | 복잡한 업무에는 기능이 부족하고 한국 업무 방식과 안 맞을 수 있음 | Zoho Inventory |

| 모듈형 오픈소스 ERP | 필요한 기능(모듈)만 골라 붙이는 공개 소프트웨어 기반 ERP | 기능 조합이 자유롭고 자동 발주 규칙이 자세히 공개됨 | 설정이 어렵고 모듈을 늘리면 비용이 늘어남 | Odoo Inventory |

우리가 노리는 자리는 "범용 ERP는 무겁고, 셀러용 도구는 발주가 약하다"는 사이입니다. 재고에서 발주까지만 가볍게 연결하는 것이 MVP의 목표입니다.

## MVP 시사점과 출처

MVP는 "재고 부족 감지 → 발주서 초안 → 공급업체 납기 관리"를 한 흐름으로 묶는 데 집중하는 것이 GAP과 가장 잘 맞습니다. 아래는 비교 결과에서 끌어낸 제안이며 확정안이 아닙니다.

1. 재고·입출고·발주·공급업체 4개 핵심 화면으로 범위를 좁히고, 회계·인사는 넣지 않습니다(이카운트·더존과 정면 경쟁을 피함).
2. 발주점 규칙과 최근 출고량으로 발주서 초안을 만드는 기능을 먼저 구현합니다(Odoo 보충 규칙을 참고).
3. AI는 수요 예측 기반 발주 추천과 자연어 질의 두 가지로 제한합니다(Katana AI Replenishment를 참고).
4. 월 정액 가격과 무료 체험 플랜을 포지셔닝에 넣습니다(이카운트·Zoho 사례).

## 제안서 연결: MVP와 GAP

제안서는 벤치마킹의 포인트를 "기존 서비스와 비교해 무엇을 단순화·차별화했는가"로 보고 있습니다. 아래 표는 MVP 기능이 위 GAP 분석의 어느 빈칸을 메우는지 연결한 것입니다.

| MVP 기능 (제안서) | 메우는 GAP | 포트폴리오 설명 문장 예시 |
| --- | --- | --- |
| 품목 + 입출고 + 현재 재고 + 발주를 한 데이터로 연결 | 채널과 ERP의 분리(판매·재고·발주 단일 데이터 모델) | "화면이 나뉘지 않고 입출고가 재고와 발주에 이어지는 최소 구조를 만들었다" |
| 공급업체 관리 + 발주 이력 | 공급업체 납기·단가 이력 관리 | "공급업체별 납기와 단가를 발주 이력에서 추적할 수 있게 했다" |
| 재고 부족 탐지 + 발주서 초안 | 재고 기반 발주서 초안 자동 생성 | "재고가 기준선 밑으로 내려가면 발주 초안을 만들어 판단 시간을 줄였다" |
| AI 발주 추천 | 수요예측 기반 발주 추천(조사 범위에서 Katana만 확인) | "추천 전후 품절 위험 품목 수를 비교했다" (실제 효과는 테스트 후 채우기) |
| 대시보드와 KPI | 초보자 온보딩 부재 | "기능 수를 줄이고 필수 지표만 한 화면에 모았다" |

가격 투명성 GAP은 이번 MVP가 풀지 않는 항목이라 표에서 빠졌습니다. 설명 문장은 예시이며, 실제 결과를 확인한 뒤에 쓰세요.

## 용어 정리

아래 용어는 이 문서와 프로젝트에서 자주 나오는 것들입니다. 수식이 있는 용어는 숫자를 대입한 계산 예시를 함께 적었습니다.

| 구분 | 용어 | 쉽게 말하면 | 예시 |
| --- | --- | --- | --- |
| 기본 개념 | SCM(공급망 관리) | 물건이 공급업체에서 우리 창고를 거쳐 고객에게 가기까지의 흐름을 관리하는 일 | 원단 공장에서 원단을 사 와 옷을 만들어 쇼핑몰 고객에게 보내는 전 과정 |
| 기본 개념 | ERP | 재고·구매·판매·회계·인사를 한 프로그램으로 묶은 업무 시스템 | 이카운트 ERP에서 판매를 입력하면 재고가 자동으로 줄어든다 |
| 기본 개념 | WMS | 창고 안 물건 위치와 입출고를 관리하는 시스템 | 상품 A가 어느 선반에 모두 몇 개 있는지 기록 |
| 기본 개념 | OMS | 여러 쇼핑몰 주문을 한곳에 모아 처리하는 시스템 | 쿠팡·스마트스토어 주문을 사방넷에서 한 번에 확인 |
| 기본 개념 | MRP(자재소요계획) | 만들 제품 수량에서 필요한 자재 양과 발주 시점을 계산하는 방식 | 의자 100개에 다리가 4개씩 필요하면 400개, 재고가 150개면 250개를 발주 |
| 기본 개념 | 3PL·풀필먼트 | 보관·포장·배송을 대신 맡아주는 물류 대행 | 파스토에 상품을 보내두면 주문이 들어올 때 대신 포장·발송 |
| 기본 개념 | FMS | 파스토가 쓰는 풀필먼트 관리 시스템 | 내 물류 메뉴에서 재고와 배송 현황 확인 |
| 배포 방식 | SaaS | 설치 없이 인터넷으로 쓰고 월 요금을 내는 소프트웨어 | 웹에서 로그인해 쓰고 월 4만원을 내는 이카운트 |
| 배포 방식 | 클라우드 | 내 컴퓨터 대신 인터넷 서버에 프로그램과 데이터를 두는 방식 | 엑셀 파일을 USB 대신 구글 드라이브에 두는 것과 비슷 |
| 배포 방식 | 온프레미스 | 회사 서버에 직접 설치해 쓰는 방식 | 회사 전산실에 서버를 두고 ERP를 설치 |
| 재고·발주 | SKU | 재고를 구분하는 최소 단위 | 같은 티셔츠도 빨강 M과 빨강 L은 각각 다른 SKU |
| 재고·발주 | 발주서(PO) | 공급업체에 "이만큼 주문합니다"라고 보내는 문서 | 원단 500m를 단가 3,000원에 주문 |
| 재고·발주 | 리드타임 | 발주하고 물건이 도착하기까지 걸리는 시간 | 주문 후 5일 뒤 입고되면 리드타임 5일 |
| 재고·발주 | 재주문점 | 재고가 이 수량 아래로 내려가면 발주하라는 기준. 공식: 일평균 판매량 × 리드타임 + 안전재고 | 하루 10개 팔고 리드타임 5일, 안전재고 20개면 10×5+20 = 70개. 재고가 70개 이하가 되면 발주 |
| 재고·발주 | 안전재고 | 판매가 늘거나 입고가 늦어질 때를 대비한 여유 재고. 계산법은 여러 가지이고 한 예는 (최대 일판매량 × 최대 리드타임) − (평균 일판매량 × 평균 리드타임) | (15×7) − (10×5) = 105 − 50 = 55개 |
| 재고·발주 | 재고 회전율 | 재고가 얼마나 빨리 팔리는지. 공식: 매출원가 ÷ 평균 재고금액 | 연 매출원가 1,200만원, 평균 재고 300만원이면 1,200÷300 = 4회 |
| 재고·발주 | 결품(품절) | 팔려는데 재고가 없는 상태 | 주문이 들어왔는데 재고가 0개 |
| 재고·발주 | FIFO | 먼저 들어온 물건을 먼저 내보내는 방식 | 유통기한이 있는 식품을 들어온 순서대로 출고 |
| 재고·발주 | Lot·시리얼 | Lot는 같은 시기에 만든 묶음 번호, 시리얼은 개별 상품 번호 | 라별 식품은 Lot, 노트북 한 대는 시리얼 |
| 재고·발주 | 로케이션 | 창고 안 보관 위치 | A동-3열-2단 |
| 재고·발주 | 바코드·RFID | 상품 정보를 읽는 줄무달 코드와 무선 태그 | 스캐너로 찍으면 입고 수량이 자동 반영 |
| 가격 표기 | 견적제 | 가격표 없이 상담 후 가격을 정하는 방식 | 더존·파스토는 문의해야 가격을 알 수 있음 |
| 가격 표기 | VAT 별도 | 표시 가격에 부가세(10%)가 따로 붙는다는 뜻 | 월 40,000원(VAT 별도)면 40,000×1.1 = 44,000원 결제 |
| 가격 표기 | 크레딧 | 기능 사용량을 세는 포인트 | 플레이오토 STANDARD의 셀핏 AI 월 2,400 크레딧 |
| 개발·기획 | MVP | 핵심 기능만 담은 최소 제품 | 재고·입출고·발주·공급업체 4개 화면만 먼저 만들기 |
| 개발·기획 | ERD | 데이터 테이블과 관계를 그린 설계도 | 상품 테이블과 발주 테이블이 상품번호로 연결 |
| 개발·기획 | API | 프로그램끼리 데이터를 주고받는 창구 | 쇼핑몰 주문을 SCM 서비스로 자동 전달 |
| 개발·기획 | EDI | 기업 간 주문서·송장을 표준 형식으로 자동 교환하는 방식 | 공급업체와 발주서를 메일 대신 시스템끼리 주고받기 |
| 개발·기획 | 온보딩 | 처음 쓰는 사람이 서비스에 적응하도록 돕는 과정 | 샘플 데이터로 첫 발주서까지 안내하는 화면 |
| 개발·기획 | AX | AI를 업무에 적용해 일하는 방식을 바꾸는 것 | 재고 데이터로 AI가 발주량을 추천 |
| 분석 | 벤치마킹 | 유사 서비스와 비교해 배울 점을 찾는 일 | 이카운트의 월 정액 가격 구조를 참고 |
| 분석 | GAP 분석 | 기존 서비스가 못 채우는 빈틈을 찾는 일 | 국내 서비스에서 발주서 초안 자동 생성을 찾지 못함 |
| 분석 | 수요 예측 | 과거 판매 데이터로 앞으로의 판매량을 추정 | 지난 4주 평균이 주 70개면 다음 주도 70개 안팔으로 추정(가장 단순한 방법) |
| 분석 | AI Replenishment | AI가 언제 얼마나 발주할지 추천하는 기능(Katana의 기능명) | 재고가 재주문점에 가까워지면 발주량을 제안 |
