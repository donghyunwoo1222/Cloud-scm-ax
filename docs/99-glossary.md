# 용어 정리

처음 보는 용어와 쉬운 설명, 예시를 모아 둡니다. 출처: `docs/01-benchmarking/benchmarking-report.md`의 용어 정리 표. 영문 약어는 알파벳순(대소문자 구분 없이), 한글 용어는 가나다순으로 정렬했습니다.

## 영문 약어

- **3PL·풀필먼트**: 보관·포장·배송을 대신 맡아주는 물류 대행 / 파스토에 상품을 보내두면 주문이 들어올 때 대신 포장·발송
- **AI Replenishment**: AI가 언제 얼마나 발주할지 추천하는 기능(Katana의 기능명) / 재고가 재주문점에 가까워지면 발주량을 제안
- **API**: 프로그램끼리 데이터를 주고받는 창구 / 화면이 서버에 "재고 목록 주세요"라고 요청, 쇼핑몰 주문을 SCM 서비스로 자동 전달
- **AX**: AI를 업무에 적용해 일하는 방식을 바꾸는 것 / 재고 데이터로 AI가 발주량을 추천
- **Case Study**: 문제 → 해결 → 결과를 이야기로 정리한 사례 문서 / 포트폴리오 README
- **company_id**: 데이터가 어느 회사 것인지 적어 둔 식별 번호 / 품목 행마다 company_id = 1 형태로 저장
- **CRUD**: 데이터를 만들고(Create) 보고(Read) 고치고(Update) 지우는(Delete) 기본 기능 / 공급업체 등록·조회·수정·삭제
- **EDI**: 기업 간 주문서·송장을 표준 형식으로 자동 교환하는 방식 / 공급업체와 발주서를 메일 대신 시스템끼리 주고받기
- **ERD**: 데이터 테이블과 관계를 그린 설계도 / 상품 테이블과 발주 테이블이 상품번호로 연결
- **ERP**: 재고·구매·판매·회계·인사를 한 프로그램으로 묶은 업무 시스템 / 이카운트 ERP에서 판매를 입력하면 재고가 자동으로 줄어든다
- **FIFO**: 먼저 들어온 물건을 먼저 내보내는 방식 / 유통기한이 있는 식품을 들어온 순서대로 출고
- **FMS**: 파스토가 쓰는 풀필먼트 관리 시스템 / 내 물류 메뉴에서 재고와 배송 현황 확인
- **GAP 분석**: 기존 서비스가 못 채우는 빈틈을 찾는 일 / 국내 서비스에서 발주서 초안 자동 생성을 찾지 못함
- **KPI**: 잘되고 있는지 숫자로 보는 핵심 지표 / 재고회전율, 품절 위험 품목 수
- **LLM**: 대화형 AI가 쓰는 대형 언어 모델 / 질문을 SQL 조회로 바꾸는 데 사용
- **Lot·시리얼**: Lot는 같은 시기에 만든 묶음 번호, 시리얼은 개별 상품 번호 / 라벨 식품은 Lot, 노트북 한 대는 시리얼
- **MRP(자재소요계획)**: 만들 제품 수량에서 필요한 자재 양과 발주 시점을 계산하는 방식 / 의자 100개에 다리가 4개씩 필요하면 400개, 재고가 150개면 250개를 발주
- **Must/Should/Could**: 기능의 중요도 분류. 반드시/가능하면/여유 있을 때 / 입출고는 Must, 자연어 질의는 Could
- **MVP**: 핵심 기능만 담은 최소 제품 / 재고·입출고·발주·공급업체 4개 화면만 먼저 만들기
- **OMS**: 여러 쇼핑몰 주문을 한곳에 모아 처리하는 시스템 / 쿠팡·스마트스토어 주문을 사방넷에서 한 번에 확인
- **RAG**: 자료를 찾아서 AI 답변에 붙이는 방식 / 운영 규칙 문서를 찾아 답변에 반영
- **SaaS**: 설치 없이 인터넷으로 쓰고 월 요금을 내는 소프트웨어 / 웹에서 로그인해 쓰고 월 4만원을 내는 이카운트
- **SCM(공급망 관리)**: 물건이 공급업체에서 우리 창고를 거쳐 고객에게 가기까지의 흐름을 관리하는 일 / 원단 공장에서 원단을 사 와 옷을 만들어 쇼핑몰 고객에게 보내는 전 과정
- **SKU**: 재고를 구분하는 최소 단위 / 같은 티셔츠도 빨강 M과 빨강 L은 각각 다른 SKU
- **VAT 별도**: 표시 가격에 부가세(10%)가 따로 붙는다는 뜻 / 월 40,000원(VAT 별도)면 40,000×1.1 = 44,000원 결제
- **WMS**: 창고 안 물건 위치와 입출고를 관리하는 시스템 / 상품 A가 어느 선반에 모두 몇 개 있는지 기록

## 한글 용어

- **견적제**: 가격표 없이 상담 후 가격을 정하는 방식 / 더존·파스토는 문의해야 가격을 알 수 있음
- **결품(품절)**: 팔려는데 재고가 없는 상태 / 주문이 들어왔는데 재고가 0개
- **납기 준수율**: 약속한 날짜에 맞게 도착한 비율 / 10건 중 8건이 제때 오면 80%
- **로케이션**: 창고 안 보관 위치 / A동-3열-2단
- **리드타임**: 발주하고 물건이 도착하기까지 걸리는 시간 / 주문 후 5일 뒤 입고되면 리드타임 5일
- **멀티테넌트**: 하나의 서비스를 여러 회사가 같이 쓰되 회사별 데이터는 서로 보이지 않는 구조 / A사 직원은 B사 재고를 볼 수 없음
- **바코드·RFID**: 상품 정보를 읽는 줄무늬 코드와 무선 태그 / 스캐너로 찍으면 입고 수량이 자동 반영
- **발주 상태**: 발주서가 어느 단계에 있는지 표시하는 값 / DRAFT(초안) → APPROVED(승인) → ORDERED(발주함) → RECEIVED(입고 완료)
- **발주서(PO)**: 공급업체에 "이만큼 주문합니다"라고 보내는 문서 / 원단 500m를 단가 3,000원에 주문
- **벤치마킹**: 유사 서비스와 비교해 배울 점을 찾는 일 / 이카운트의 월 정액 가격 구조를 참고
- **수요 예측**: 과거 판매 데이터로 앞으로의 판매량을 추정 / 지난 4주 평균이 주 70개면 다음 주도 70개 안팎으로 추정(가장 단순한 방법)
- **안전재고**: 판매가 늘거나 입고가 늦어질 때를 대비한 여유 재고. 계산법은 여러 가지이고 한 예는 (최대 일판매량 × 최대 리드타임) − (평균 일판매량 × 평균 리드타임) / (15×7) − (10×5) = 105 − 50 = 55개
- **온보딩**: 처음 쓰는 사람이 서비스에 적응하도록 돕는 과정 / 샘플 데이터로 첫 발주서까지 안내하는 화면
- **온프레미스**: 회사 서버에 직접 설치해 쓰는 방식 / 회사 전산실에 서버를 두고 ERP를 설치
- **입출고 이력**: 현재 수량만 아니라 변경 기록을 모두 남기는 것 / "3월 2일 +100, 3월 5일 -3"이 쌓여 현재 97이 됨
- **장기재고**: 오래 팔리지 않고 창고에 남아 있는 재고 / 6개월째 출고가 없는 품목
- **재고 회전율**: 재고가 얼마나 빨리 팔리는지. 공식: 매출원가 ÷ 평균 재고금액 / 연 매출원가 1,200만원, 평균 재고 300만원이면 1,200÷300 = 4회
- **재주문점**: 재고가 이 수량 아래로 내려가면 발주하라는 기준. 공식: 일평균 판매량 × 리드타임 + 안전재고 / 하루 10개 팔고 리드타임 5일, 안전재고 20개면 10×5+20 = 70개. 재고가 70개 이하가 되면 발주
- **크레딧**: 기능 사용량을 세는 포인트 / 플레이오토 STANDARD의 셀핏 AI 월 2,400 크레딧
- **클라우드**: 내 컴퓨터 대신 인터넷 서버에 프로그램과 데이터를 두는 방식 / 엑셀 파일을 USB 대신 구글 드라이브에 두는 것과 비슷
