- 발주서 문서(#157, `app/services/po_document.py`): 화면과 엑셀은 같은 `build_document` 값을 쓴다(숫자 계산은 서버에서 한 번). 부가세 = 공급가액 합계 ÷ 10 원 미만 버림, 줄별 세액 없음(2026-11-09 사용자 결정). 한글 금액은 1도 읽는다(`일천`). 문서는 APPROVED·ORDERED·RECEIVED만(DRAFT·CANCELLED 409). 납품장소가 비면 회사 주소, 지불조건은 발주서를 만들 때 공급업체 값을 복사한다(이후 공급업체를 바꿔도 안 바뀜). 발주일자는 작성일(서울). 인쇄는 `globals.css`의 `@media print`가 사이드 메뉴·상단 바·`.no-print`를 숨기고 A4 한 장에 `.po-paper`만 낸다. 엑셀은 `<a download>` 링크 하나(GET, 쿠키 자동). 승인 전 경고: DRAFT 발주서 상세가 `GET /company`를 읽어 사업자번호·대표자·주소·연락처 중 빈 칸이 있으면 승인 버튼 아래에 경고 한 줄(관리자는 `/company` 링크, 담당자는 "관리자에게 요청")을 보이고, 승인 버튼은 같은 문장으로 확인창을 띄운다. 화면에서만 처리하며 서버 규칙(R5)은 그대로다. 지불조건·납품장소·메모는 비어도 경고하지 않는다.
- 메일 발송(#158, `app/services/po_mail.py`): 메일 문장은 고정 틀이고 사용자는 앞머리(`intro`)만 보낸다. 받는 사람·제목·본문 숫자·첨부는 서버가 `build_document` 값으로 만든다(본문으로 받는 주소를 바꿀 수 없다). 순서는 발주서 행 잠금 → 상태·이메일·설정 검사 → SMTP 발송(시간 제한 10초) → 성공 시 ORDERED + 기록 → 커밋. 실패는 아무것도 안 바꾸고 502. 더블클릭은 잠금 뒤 두 번째 요청이 ORDERED 를 보고 409 `ALREADY_ORDERED`, 다시 보내기는 화면 확인 후 `resend: true`(기록은 마지막 1건 덮어쓰기). 메일은 나갔는데 커밋이 실패하면 500 `MAIL_SENT_NOT_SAVED`로 "다시 보내지 말고 확인 후 주문 완료 표시"를 안내한다(SMTP 와 DB 를 한 번에 확정할 수 없어 남는 한계). 화면은 "보냈습니다"까지만 말하고 공급업체 수신을 주장하지 않는다. 보내는 주소는 `SMTP_FROM` 하나 + `Reply-To` 보낸 사람. 테스트는 `po_mail.deliver`를 monkeypatch 로 바꿔 끼운다. 서버 PDF 는 `po_document.build_pdf`(fpdf2, 같은 칸·같은 숫자, 모양은 비슷하게). 사용자 글자는 `html.escape` 후 넣고 미리보기 iframe 은 `sandbox="allow-same-origin"`(스크립트 불가).
- 업로드 요청(#154): 프런트 `api()`에 `FormData`를 body 로 주면 JSON 대신 multipart 로 보낸다(Content-Type 은 브라우저가 붙인다). 파일과 함께 보낼 설정은 `options` 한 칸에 JSON 글자로 넣는다.
- 데스크톱 표 칸선(#146): 730px 이상에서 `table`·`th`·`td`에 `1px solid var(--color-border-strong)` 테두리를 준다. 기존 구분선 색(`--color-border`)은 세로선으로 쓰면 거의 안 보여서 한 단계 진한 기존 변수를 쓴다. 모바일(730px 미만)은 압축 행·가로 스크롤 표라 그대로 둔다. 새 표도 이 규칙을 자동으로 따르므로 칸선을 따로 만들지 않는다.
- 사이드 메뉴 접기(#151): 데스크톱 햄버거(`.sidebar-toggle`)가 `aside[data-collapsed]`를 바꾼다. 접히면 `.sidebar-brand`·`.side-nav`는 `display: none !important`(메뉴 배치가 inline style 이라 !important 필요)이고 폭은 56px 이다. 접힘 값은 `localStorage` 의 `sidebar-collapsed`("1"/"0")이며 읽고 쓰는 곳은 try/catch 로 감싼다. 모바일(730px 미만)은 이 규칙이 적용되지 않는다.
- 표 안 동작(#149): 목록 표에 줄마다 테두리 버튼 칸을 두지 않는다. 열기·선택은 이름을 `button.text-button`(글자처럼 보이는 버튼, 누르는 칸 24px 이상)으로, 되돌리기 번거로운 비활성은 수정 폼이나 상세 화면 안에 둔다. 칸 아래 설명 글자 대신 말풍선이 필요하면 재고 현황의 `StatusTip`처럼 popover(맨 위 층)로 띄운다(표 가로 스크롤 상자에 잘리지 않게). 공급업체 상세의 수정은 `/suppliers?edit=번호`로 목록의 수정 폼을 연다. 칸선을 넣지 않을 표는 `className="plain-table"`을 단다(대시보드 막대 표). 보조 설명 글자는 줄글로 깔지 않고 `lib/tip.tsx`의 `InfoTip`·`Tip`(말풍선)으로 둔다. 목록에서 이름을 눌러 위쪽 등록·수정 폼(`<details>`)을 열 때는 `className="smooth-details"`를 달고 `scrollIntoView({behavior: "smooth"})`로 올라간다(펼침은 CSS `::details-content` 전환, 움직임 줄이기를 켜면 바로 열림). 펼치는 동안에는 내용이 숨겨져 있어 포커스는 `requestAnimationFrame` 안에서 준다.

- 모바일 입력칸(#141): 입력 항목은 `<Field label="…" className="…">`로 쓴다(라벨 글자가 `field-label` span 으로 감싸진다). 데스크톱은 라벨이 입력칸 위, 730px 미만은 라벨이 위쪽 테두리에 걸린다. 폼에는 `form-compact field-form` 클래스를 달고 짧은 항목은 `field-half`(두 칸), 남는 폭을 채울 항목은 `field-grow`를 단다. 긴 라벨은 `short`로 모바일 전용 짧은 라벨을 준다(한 줄 12px, 반 폭에 들어가는 길이). 선택지 글자가 긴 선택칸(예: 실사 조정 방향)은 두 칸으로 묶지 않는다. 모바일에서 포커스는 바깥 윤곽선 대신 파란 테두리 + 안쪽 1px 선이다(바깥 윤곽선이 라벨을 가로지른다). 라벨 뒤 배경은 위쪽 절반 투명 + 아래쪽 절반 카드색이라 카드 안·페이지 배경 위 모두에서 쓸 수 있다.
- 모바일 간격 토큰(#139): 화면 여백은 `--page-pad`(24px, 모바일 16px)·`--card-pad`(16px, 12px)·`--section-gap`(32px, 24px)·`--field-gap`(16px, 12px)를 쓰고 새 화면·카드·폼도 이 토큰을 따른다(직접 px를 쓰지 않는다). 폼은 `form-compact` 클래스를 달면 모바일에서 항목이 한 줄씩이고, 짧은 항목에 `field-half`를 달면 두 칸씩 놓인다. 순서가 필요하면 모바일 전용 CSS `order` 클래스를 쓰고 DOM 순서는 바꾸지 않는다. 선택 항목 접기는 `data-box-open`처럼 폼 속성으로 숨기고, 값이 하나라도 있으면 펼쳐 필수 칸이 숨지 않게 한다. 같은 우선순위 CSS는 나중 규칙이 이기므로 기본(데스크톱) 규칙을 모바일 `@media`보다 앞에 둔다.
- 모바일 표 대신 압축 행(#136): 730px 미만에서 표를 담은 상자에 `table-view`, 같은 데이터의 2줄 목록에 `compact-list`(`compact-row`·`compact-main`·`compact-sub`·`compact-note`)를 둔다. 1줄은 이름과 핵심 수량, 2줄은 SKU·유형·날짜 같은 보조 정보이고, 행 오른쪽 버튼이 필요하면 `compact-with-action`을 쓴다. 기본(데스크톱) 숨김 규칙은 모바일 `@media`보다 앞에 둔다. 관리 화면(품목·공급업체·사용자·재고 현황·발주 목록)은 표와 가로 스크롤을 유지한다.
- 모바일(730px 미만, #136): 메뉴는 왼쪽 드로어(폭 min(320px, 85vw)), 본문 위에는 56px 앱바(햄버거 + 현재 화면 이름)만 둔다. 내 정보와 로그아웃은 드로어 안(로그아웃은 맨 아래 고정), 데스크톱은 기존 상단 바를 쓴다. 드로어를 열면 뒤 화면은 `inert`, 스크롤 잠금, Esc·스크림·닫기 버튼·메뉴 선택으로 닫는다. 누르는 칸의 최소 높이는 토큰 `--control-min`(데스크톱 36px, 모바일 44px)과 `--chip-min`(28px, 모바일 44px)을 쓰고 새 버튼·입력칸도 이 토큰을 따른다. 모바일 입력칸 글자는 16px 이상, 정수 칸은 `inputMode="numeric"`. 주소를 읽는 훅(`usePathname`·`useSearchParams`)은 항상 Suspense 안에서 쓴다.
- 품목 선택(#128): 품목명·SKU를 서버 전체에서 검색하고 입력 바로 아래 후보를 선택한다. 등록에 쓸 품목은 후보를 확정할 때 바뀐다. 검색어만 바꾼 상태에서는 저장을 막는다. 입출고는 비활성 포함, 발주 새 줄은 활성만 검색한다.

- 품목별 재고 추이(#126): 서울 오늘 포함 30일을 기간 전 잔액과 날짜별 순변동으로 계산한다. 정정은 원래 날짜에 반영한다. 첫 기록 전에는 빈 값이고, 오늘은 조회 시점까지다. 그래프는 재고 현황에서 품목을 선택할 때만 조회한다.

- 품목 목록(#106)의 기본 공급업체 필터는 검색어·품목 활성 조건과 함께 서버에서 먼저 적용한 뒤 전체 건수를 세고 페이지를 나눈다. 기존 품목을 찾는 필터에는 비활성 업체도 표시하고, 품목에 새로 연결하는 업체는 활성만 선택할 수 있다.
