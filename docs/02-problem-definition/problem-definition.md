# 문제 정의: 중소 유통업체 persona·저니·problem statement

Nov 2, 2026 · @우동현

## 대상과 전제

이 문서의 주 대상은 온라인 판매를 병행하는 직원 5\~30명 규모의 도소매 유통업체이고, 제조업은 확장 시나리오로만 다룹니다. 도소매를 고른 이유는 SKU, 재고, 발주, 입출고가 업무의 중심이라 MVP 범위(재고·입출고·발주·공급업체)와 가장 잘 맞기 때문입니다.

**중요: 아래 persona와 pain point는 가설입니다.** 인물 이름과 수치는 가상이며, 공개 자료와 벤치마킹 결과로 세운 뒤 인터뷰로 검증해야 합니다.

| 근거 | 내용 | 한계 |
| --- | --- | --- |
| 벤치마킹 GAP 분석 | 재고→발주서 초안 자동화, 공급업체 납기·단가 이력, 판매·재고·발주 단일 데이터 모델, 초보자 온보딩 부재 | 기능 비교 중심이라 실제 업무 불편은 직접 확인한 것이 아님 |
| [Blue Ridge·SmartBrief 도매 공급망 조사 2020](https://www.mdm.com/article/operations/distributors-report-difficulties-with-managing-inventory/) | 도매업체 73%가 복잡한 고객 수요 패턴, 75%가 수요 변동성 증가를 재고관리 과제로 꼽음. 현재 재고로 전체 수요를 충족하는 업체는 3.36% | 미국 도매업 대상, 2020년 자료, 표본 크기 미확인 |

한국 중소 유통업체에 대한 정량 실태조사는 이번 검색에서 확인하지 못했습니다. 그래서 pain point의 우선순위는 근거 강도를 함께 표시하고, 인터뷰에서 확정합니다.

## Persona: 가상 인물 3명 (가설)

세 인물은 모두 가상이며, 한 유통업체 안에서 재고 데이터를 서로 다르게 쓰는 역할로 나눴습니다. 인터뷰 후 수정합니다.

| 항목 | 김서연 (구매·재고 담당) | 박정호 (대표) | 이민수 (창고 담당) |
| --- | --- | --- | --- |
| 회사 가정 | 직원 12명 생활용품 도매, 스마트스토어·자사몰 병행, SKU 약 800개 | 같은 회사 | 같은 회사 |
| 핵심 목표 | 품절 없이 적정 재고 유지, 발주를 빠르게 끝내기 | 현금이 재고에 묶이지 않게 하고 매출 대비 재고 규모 파악 | 입출고 실수 없이 하루 출고량 소화 |
| 현재 도구 (가설) | 엑셀, 카카오톡·전화로 발주, 판매 채널 관리자 페이지 | 엑셀 요약본, 회계 프로그램, 구두 보고 | 종이 출고지시서, 엑셀, 메신저 |
| 하루 중 가장 큰 답답함 | 채널별 판매량을 모아 재고를 맞추는 데 매일 시간이 듦 | 지금 재고가 얼마이고 어디에 묶였는지 한눈에 안 보임 | 시스템 재고와 선반 재고가 달라 찾는 시간이 늘어남 |
| 시스템에 바라는 점 | 발주 시점과 수량을 알려주고 발주서를 대신 만들어 주기 | 재고 금액, 회전율, 부진 재고를 보여주는 요약 | 폰으로 입출고를 바로 기록하고 위치를 확인 |
| 도입 장벽 | 새 도구 학습 시간 부족, 기존 엑셀 이력 이전 | 월 비용과 도입 효과 불확실 | 현장에서 입력할 시간이 없음 |

MVP의 주 사용자는 김서연입니다. 발주가 재고 데이터의 최종 소비처이고, 벤치마킹에서 확인한 GAP(재고 기반 발주서 초안, 공급업체 이력)가 이 역할에 가장 직접 연결되기 때문입니다. 박정호는 대시보드 사용자, 이민수는 입출고 입력자로 둡니다.

## Pain point (가설)

가장 먼저 풀 pain point는 "무엇을 언제 얼마나 발주할지 감으로 정한다"이며, 근거 강도가 높고 MVP로 바로 풀 수 있습니다. 근거 강도는 "높음"(벤치마킹과 공개 자료가 함께 뒷받침), "중간"(한쪽만 뒷받침), "낮음"(추정)으로 표시했습니다.

| # | Pain point | 관련 persona | 근거 | 강도 | MVP 우선순위 |
| --- | --- | --- | --- | --- | --- |
| 1 | 발주 시점과 수량을 경험과 감으로 정해 품절 또는 과잉재고가 생김 | 김서연, 박정호 | 벤치마킹 GAP(재고 기반 발주 추천은 Katana만 확인), 도매업 조사에서 수요 변동성 75% | 높음 | 상 |
| 2 | 엑셀 재고와 실제 재고가 어긋나 매번 확인 작업이 필요함 | 이민수, 김서연 | 아이퀘스트 블로그의 데이터 불일치 리스크(홍보성), 벤치마킹에서 재고 실사 기능 차이 | 중간 | 상 |
| 3 | 스마트스토어·자사몰 등 채널별 판매와 재고가 따로 움직임 | 김서연 | 벤치마킹 GAP(채널 도구와 ERP 분리), 블로그의 멀티채널 동기화 지연 | 높음 | 중 |
| 4 | 발주서를 매번 수기로 만들고 공급업체별 납기·단가 이력이 남지 않음 | 김서연 | 벤치마킹 GAP(공급업체 납기·단가 이력 관리 부재) | 중간 | 상 |
| 5 | 담당자가 바뀌거나 자리를 비우면 입출고 이력과 단가 변동을 추적하기 어려움 | 박정호 | 블로그의 이력 추적 리스크(홍보성) | 낮음 | 중 |
| 6 | 기존 ERP는 기능이 많아 처음 쓰기 어렵고 도입 비용이 부담됨 | 박정호 | 벤치마킹 GAP(초보자 온보딩, 가격 투명성) | 중간 | 중 |

1번과 4번은 "재고 → 발주서 초안" 하나의 흐름으로 묶어 MVP 핵심 기능으로 삼습니다. 2번은 입출고 기록 화면으로, 3번은 판매 주문이 재고를 차감하는 단일 데이터 모델로 풉니다. 5번과 6번은 MVP 이후로 미룹니다.

제조업 확장 시나리오에서는 1번이 "자재 소요량 기반 발주"로 바뀌고 BOM(자재 명세서) 관리가 추가로 필요합니다. 이 부분은 이번 MVP 범위에서 제외합니다.

## User journey: 김서연의 하루 (재고 확인 → 발주 → 입고 → 출고)

주 사용자 김서연이 재고를 확인하고 발주해 입고·출고까지 거치는 흐름이며, 감정은 가설입니다. 감정이 가장 나빠지는 곳은 2단계(발주 결정)이고 MVP도 여기에 집중합니다.

| 단계 | 행동 | 감정 (가설) | Pain point | MVP 해결 지점 |
| --- | --- | --- | --- | --- |
| 1. 재고 확인 | 엑셀을 열고 채널별 판매량을 복사해 현재 재고를 맞춘다 | 번거로움, 불안 | #2 엑셀과 실제 재고 불일치, #3 채널별 재고 분리 | 판매 주문이 들어오면 재고가 자동 차감되는 단일 데이터 모델과 재고 현황 화면 |
| 2. 발주 결정 | 남은 수량과 지난 판매를 보고 감으로 발주 시점과 수량을 정한다 | 가장 큰 스트레스, 품절 걱정 | #1 감에 의한 발주 | 일평균 판매량 × 리드타임 + 안전재고로 계산한 재오더 포인트 알림과 발주 추천 수량 |
| 3. 발주서 작성 | 공급업체별로 엑셀 발주서를 만들어 카톡·메일·전화로 보낸다 | 반복 작업에 지침 | #4 수기 발주서, 납기·단가 이력 없음 | 재고 부족 품목을 모아 공급업체별 발주서 초안을 자동 생성하고 단가·납기 이력을 저장 |
| 4. 입고 | 상품이 도착하면 발주서와 수량을 대조하고 엑셀에 입력한다 | 확인 부담, 실수 우려 | #2 입력 누락과 불일치 | 발주 대비 입고 수량 대조와 입고 등록(부분 입고 지원) |
| 5. 출고 | 주문이 들어오면 창고 담당자가 출고하고 수량을 기록한다 | 바쁨, 기록 소홀 | #2 출고 후 재고 반영 지연 | 출고 등록 즉시 재고 반영, 모바일 화면에서 입력 |
| 6. 점검 | 주기적으로 재고를 세어 시스템과 맞춰 본다 | 막막함 | #2, #5 이력 추적 어려움 | 입출고 이력 조회와 실사 후 재고 조정 기록 |

흐름에서 MVP는 1\~5단계를 지원하고 6단계는 이력 조회 수준으로만 다룹니다.

## Problem statement

온라인 채널을 병행하는 중소 도소매 유통업체의 구매·재고 담당자는 재고와 판매 데이터가 흐트러져 있어 발주 시점과 수량을 감으로 정하고, 그 결과 품절과 과잉재고를 반복합니다 (가설).

| 항목 | 내용 |
| --- | --- |
| 누가 | 직원 5\~30명 규모, 온라인 판매를 병행하는 도소매 유통업체의 구매·재고 담당자(김서연)와 대표(박정호) |
| 어떤 상황에서 | 엑셀과 채널별 관리자 페이지를 오가며 재고를 맞추고, 공급업체에 수기로 발주할 때 |
| 무엇이 어렵다 | 현재 재고가 정확하지 않고, 언제 얼마나 발주할지 근거가 없으며, 공급업체 납기·단가 이력이 남지 않음 |
| 기존 대안의 한계 | 엑셀은 실시간 반영과 이력이 어렵고, 기존 ERP·WMS는 기능이 많아 초보자에게 무겁고, 발주 추천은 확인한 범위에서 Katana만 제공함(벤치마크 조사) |
| 원하는 결과 | 품절·과잉재고 감소, 발주 작업 시간 단축 (목표 수치는 인터뷰 후 설정) |

**How Might We:** 어떻게 하면 초보자도 판매 주문, 재고, 발주를 한 데이터로 이어 발주 결정을 쉽게 만들 수 있을까?

해결 방향은 세 가지입니다. 판매·재고·발주를 잇는 단일 데이터 모델, 재오더 포인트 기반 발주서 초안 자동 생성(AX는 이 단계에서 수요 예측으로 확장), 공급업체 납기·단가 이력 관리입니다.

## MVP 범위 (제안서 기준)

제안서의 MVP 범위(4\~8주 내 완성 가능한 기능으로 제한)에 맞춰, 위 pain point를 어떤 기능이 풀지 아래 표로 정리했습니다.

| 구분 | 기능 | 풀어주는 pain point | 설명 |
| --- | --- | --- | --- |
| 필수 | 회사/사용자 | 전체 | 회사 단위로 데이터를 분리하고 로그인과 기본 역할을 둠 |
| 필수 | 공급업체 | #4 | 공급업체 등록·조회·수정, 납기·단가 이력의 기반 |
| 필수 | 품목(SKU)/자재 | #1 | 단가, 안전재고, 리드타임을 품목에 저장 |
| 필수 | 입고/출고 | #2, #3, #5 | 수량 변경과 이력을 함께 기록 |
| 필수 | 현재 재고 | #2 | 품목별 가용 재고와 상태 표시 |
| 필수 | 발주 | #1, #4 | 발주 생성, 상태 변경, 입고 연결 |
| 필수 | 대시보드 | #1, #2 | 재고 부족, 장기재고, 입출고 현황 |
| AX 필수 후보 | AI 발주 추천 | #1 | 최근 출고, 현재고, 리드타임 기반 제안 |
| AX 선택 | 자연어 SCM 질의 | #1, #2 | "다음 주 부족 예상 품목은?" 같은 질문 |
| 후순위 | 고급 수요예측 | #1 | MVP 안정화 이후 확장 |
| 제외 | 회계·급여·전사 ERP | - | 범위 과다 방지 |

**데이터 구조 원칙 두 가지.** 첫째, 모든 업무 데이터에 company\_id를 붙여 회사별로 데이터를 분리합니다. 둘째, 재고는 현재 수량만 저장하지 않고 입출고 이력을 남겨 "왜 이 수량인지" 설명할 수 있게 합니다. 발주 상태는 DRAFT → APPROVED → ORDERED → RECEIVED (또는 CANCELLED) 흐름으로 둡니다.

**판매 채널 처리 (제 제안, 확인 필요).** 제안서의 MVP 목록에는 판매 주문과 채널 연동이 없습니다. 그래서 pain point #3(채널별 재고 분리)은 MVP에서 "출고 등록 시 판매 채널을 기록"하는 수준으로만 다루고, 스마트스토어 같은 실제 채널 API 연동은 후순위로 둡니다. 이 방향이 맞는지 알려 주세요.

## AX 적용 지점

AX는 "AI를 붙였다"가 아니라 어떤 업무 판단을 줄이는지로 설명해야 합니다(제안서 8장). 아래는 제안서의 우선순위를 이 문서의 pain point와 연결한 것이며, MVP에서는 1\~2번을 먼저 만듭니다.

| 우선순위 | AX 기능 | 아이디어 | 연결되는 pain point | 줄여주는 판단 |
| --- | --- | --- | --- | --- |
| 1 | 재고 부족·과잉 탐지 | 현재고 + 출고 추세 + 안전재고로 위험 표시 | #1, #2 | "지금 무엇이 위험한가"를 매번 엑셀로 확인하는 일 |
| 2 | 적정 발주량 추천 | 평균 수요, 리드타임, 안전재고를 조합해 제안 | #1, #4 | "얼마나 발주할지"를 감으로 정하는 일 |
| 3 | 자연어 운영 질의 | LLM이 질문을 SQL·분석 요청으로 바꾸고 결과를 요약 | #1, #2 | 화면을 여러 개 넘기며 수치를 찾는 일 |
| 4 | 관리자 주간 요약 | 재고 이슈, 입출고, 발주 현황을 자동 요약 | #2, #5 | 대표에게 매주 구두로 보고하는 일 |
| 5 | 공급망 리스크 알림 | 납기 지연·재고 부족·공급업체 이슈 표시 | #4 | 공급업체 문제를 늦게 알게 되는 일 (향후 고도화) |

추천 로직은 앞에서 설명한 재주문점 공식(일평균 판매량 × 리드타임 + 안전재고)을 출발점으로 삼습니다. 단순한 공식으로 시작해 사용자 테스트로 효과를 확인한 뒤 수요 패턴 반영이나 LLM 보조로 확장하는 순서가 현실적이라고 봅니다. AX 검증 기준(입력, 출력, 평가 방법)은 다음 단계인 AX 설계에서 정합니다.

## 검증 계획과 MVP 연결

가설은 사용자 인터뷰 5\~10명(제안서 6.1 기준)으로 확인하고, 확인된 pain point만 MVP 범위에 넣습니다. 인터뷰 대상은 도소매·온라인 쇼핑몰 운영자와 구매·재고 담당자입니다 (후보는 아직 정해지지 않았습니다).

**인터뷰 질문 (예시)**

1. 최근에 품절이나 과잉재고로 곤란했던 일을 구체적으로 말씀해 주세요. (pain point #1)
2. 발주량은 지금 어떤 기준으로 정하시나요? (#1)
3. 엑셀 재고와 실제 재고가 다른 걸 발견한 적이 있나요? 그때 어떻게 해결했나요? (#2)
4. 판매 채널이 여러 개일 때 재고는 어떻게 맞추나요? (#3)
5. 발주서는 어떻게 만들고 어떤 수단으로 보내나요? 납기·단가는 어디에 기록하나요? (#4)
6. 새 도구를 쓸 때 가장 크게 망설이게 되는 점은 무엇인가요? (#6)

**성공 기준 (잠정)**

| 지표 | 잠정 기준 | 측정 방법 |
| --- | --- | --- |
| 가설 검증 | 인터뷰이른 중 과반수가 pain point #1을 경험 | 인터뷰 정리표 |
| 발주서 작성 시간 | 수기 대비 단축 (기준 시간은 인터뷰에서 측정) | 사용자 테스트 |
| 재고 일치율 | 시스템 재고와 실사 재고 비교 | 샘플 데이터 테스트 |

**대표 사용자 테스트 시나리오.** 신규 품목 등록 → 입고 → 출고 → 재고 부족 확인 → 발주 생성 순서로 진행하고, 테스트 전후 화면과 기능을 비교해 개선 근거를 남깁니다. 대상은 소규모 사업자, 유통·물류 경험자, 동료 학습자 5\~10명입니다.

**화면에 넣을 KPI.** 재고회전율, 품절 위험 품목 수, 안전재고 미만 품목, 장기재고, 월 입출고량, 발주 리드타임, 공급업체별 납기 준수율(샘플 데이터 기반 가능)입니다. AI 추천을 적용하면 추천 전후를 비교할 기준도 미리 정의합니다.

**MVP 연결:** pain point #1\~#4는(#3은 출고 시 채널 기록 수준) 재고·입출고·발주·공급업체 관리 기능으로, #5·#6은 MVP 이후 과제로 이어집니다. 다음 단계는 확정된 문제를 바탕으로 한 기능 정의와 ERD 설계입니다.
