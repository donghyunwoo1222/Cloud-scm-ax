# 열린 질문 정리와 결정 (6단계 시작 전)

## 확정
- 이유 문구: 규칙 기반 문장 틀, LLM 다듬기는 Could
- 품목에 기본 공급업체 1개 지정 필드 포함
- 리드타임: 공급업체별로 저장. 같은 공급업체에 한 번에 주문한 품목은 같이 들어오므로 리드타임이 같다. 품목의 리드타임 = 기본 공급업체의 리드타임. 품목별 예외 값은 후순위
- 판매량 집계: 판매 출고만 포함. 출고 유형(판매/폐기·파손/기타) 구분 필요
- 부분 입고 후 취소: MVP에서는 불가
- 실사 차이: 조정 이력(ADJUSTMENT, 사유 필수)으로 기록. 재고 = 이력 합계 원칙 유지
- 발주 없는 입고는 "직접 입고"로 허용

## 이슈 #2~#8 열린 질문 반영 (제안안)
- 삭제 정책(#3, #4): 이력이 있는 공급업체·품목은 삭제하지 않고 비활성(is_active) 처리. 비활성은 새 발주·입출고 선택 목록에서만 숨김
- 직원 초대(#2): 관리자가 직원 계정을 직접 생성(이메일+임시 비밀번호). 이메일 발송 초대는 후순위
- 초과 입고(#5): 발주 수량 초과 입고는 차단하고 안내 문구 표시
- 부분 입고 후 상태(#7): 일부 입고 후에도 ORDERED 유지, 누적 입고량 = 발주 수량이면 RECEIVED
- 승인 생략(#2, #7): MVP는 생략 없음. 관리자가 직접 만든 발주도 승인 1번 유지
- 추천 계산 시점: 추천 화면을 열거나 버튼을 누를 때 계산 (아키텍처 설계에서 확정)
